# Color

DevMentor is warm-neutral with **one** muted action colour. The base stays on warm greys; the petrol action colour marks the one thing to do on a screen, active states, links and focus — nothing else.

Sources: warm greys instead of cold ones (R01.4), one muted action colour (W01, T1), one primary element per screen (R01.5, Z1). Values live only in `packages/ui/src/styles/tokens.css`; components use the semantic tokens below through Tailwind classes (`bg-primary`, `text-muted-foreground`, `border-input` …).

## Rules

| Rule | Source |
| --- | --- |
| Use semantic tokens only. Raw `--raw-*` values are private to `tokens.css`. | tokeny.md (layers), Z14 |
| At most one `primary` button (CTA) per screen; other actions are outline or ghost. | R01.5, W01, Z1 |
| Links inside text use `primary` **and** an underline — colour is never the only signal. | Z2, WCAG 1.4.1 |
| Active state (selected nav item, selected slot, active tab) = `primary/10` (light) or `primary/15` (dark) background with `foreground` or `primary` text. No new colour. | Z3, T1 |
| `border` is decoration (row dividers). It never marks the edge of a control — use `input` for that. | R01.3, WCAG 1.4.11 |
| Status, errors and selection are never shown by colour alone: add text, an icon with a label, or both. | WCAG 1.4.1 |
| No gradients, glass, glow or translucent cards. | AR01, Z12 |
| `accent` in shadcn means **hover surface**, not an accent colour. Never use it to highlight. | tokeny.md |

**Note on the `/50` row:** it measures a ring at 50 % opacity (blended over the page). shadcn's default `ring-ring/50` fails 3 : 1 in the light theme, which is why the primitives use the ring at full colour (Z7, T6).

**Known limits:** `primary-foreground` on `primary/90` is 4.99 : 1 in light — a hover must not get lighter than `/90`. `input` on `card` is 3.18 : 1 in dark — lightening `card` in dark breaks it.

**Decided, implemented in stage 2:** text on `destructive` gets a semantic `--destructive-foreground` (light `warm-gray-99`, dark `warm-gray-17`) instead of the palette class `text-white`; in the dark theme the destructive button uses full `destructive` instead of `destructive/60` (P9, accepted 2026-10-19). Its contrast pairs are added to the table above when the token is written.

## How to change a colour

1. Change the value in `tokens.css` (raw layer) — never in a component.
2. Open this page in both themes and check that no pair shows **FAIL**.
3. Run `npm run lint:tokens` and `npm run test:storybook`.
