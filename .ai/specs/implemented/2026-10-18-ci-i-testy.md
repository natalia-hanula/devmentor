# GitHub CI, testy jednostkowe ze 100% pokryciem i testy integracyjne

- **Status:** zaakceptowana 2026-10-18 — zakres z polecenia człowieka; decyzje wykonawcze poniżej do przeglądu w PR.

## Cel

Każdy pull request automatycznie sprawdza build, lint (z typecheckiem), testy jednostkowe ze 100% pokryciem oraz testy integracyjne na tymczasowym PostgreSQL (testcontainers) z uruchomioną aplikacją, testowaną przez API i przez przeglądarkę (`agent-browser`).

## Zakres

### Wchodzi

- `.github/workflows/ci.yml`: zadania `lint` (ESLint + typecheck), `unit` (Vitest + pokrycie 100%), `build` (bez bazy i bez `.env`), `integration` (testcontainers + `next start` + `agent-browser`).
- Testy jednostkowe: Vitest + `@vitest/coverage-v8`, progi 100% (linie, gałęzie, funkcje, instrukcje); komponenty React przez Testing Library w `jsdom`.
- Testy integracyjne w `tests/integration/` (osobna konfiguracja Vitest, poza `npm test`): `globalSetup` startuje PostgreSQL (testcontainers), wykonuje migracje, uruchamia zbudowaną aplikację na wolnym porcie i czeka na `/api/health`.
- Reguła 100% pokrycia w AGENTS.md.
- Testy jednostkowe pokrywające 100% istniejącego kodu.

### Nie wchodzi

- Deployment, raporty pokrycia w zewnętrznych serwisach, testy wydajnościowe.

## Decyzje wykonawcze

1. **Zakres pokrycia** = cały kod TS/TSX w `packages/*/src/**` i `packages/app/app/**`. Wyłączone wyłącznie: migracje (`packages/db/migrations/**` — wykonuje je setup testów integracyjnych), pliki konfiguracyjne (`*.config.ts`, `next.config.ts`, `mikro-orm.config.ts`) i deklaracje typów (`*.d.ts`). Bez komentarzy `v8 ignore`.
2. **Podział testów:** jednostkowe = bez bazy i bez sieci zewnętrznej (`packages/*/test/**`, `npm test`); integracyjne = prawdziwy PostgreSQL i działająca aplikacja (`tests/integration/**`, `npm run test:integration`). Dotychczasowy integracyjny test `TechnologyService` przenoszony do `tests/integration/`; w testach jednostkowych serwis dostaje atrapę `EntityManager`.
3. **Lokalnie bez Dockera:** `INTEGRATION_DATABASE_URL` wskazuje istniejącą bazę (np. Postgres z Homebrew) zamiast kontenera; setup czyści jej schemat przed migracjami. W CI zmienna jest pusta → testcontainers.
4. **`tests/integration/` to katalog, nie pakiet workspace** — nowy pakiet wymagałby osobnej zgody (AGENTS.md).
5. **`agent-browser`** jako devDependency w roocie (natywna binarka w paczce; `postinstall` niepotrzebny). W CI przeglądarka instalowana przez `agent-browser install --with-deps`.
6. Narzędzia testowe (Vitest, coverage, Testing Library, jsdom, testcontainers, agent-browser) w głównym `package.json`, zgodnie z regułą „narzędzia całego repo w roocie”.

## Kryteria akceptacji

- [x] `npm test` uruchamia testy jednostkowe i kończy się błędem, jeśli pokrycie któregokolwiek pliku z zakresu spadnie poniżej 100%.
- [x] Pokrycie istniejącego kodu: 100% linii, gałęzi, funkcji i instrukcji.
- [x] `npm run test:integration` z `INTEGRATION_DATABASE_URL` przechodzi lokalnie (migracje, API, przeglądarka).
- [x] Workflow CI uruchamia się dla PR; zadania `lint`, `unit`, `build`, `integration` przechodzą w GitHub Actions (testcontainers sprawdzane tylko tam).
- [x] AGENTS.md zawiera regułę 100% pokrycia dla każdej nowej funkcji oraz opis obu rodzajów testów.
