## Plan

1. Narzędzia: `@vitest/coverage-v8`, Testing Library, `jsdom`, `testcontainers`, `@testcontainers/postgresql`, `agent-browser`.
2. Konfiguracja Vitest: projekty `core`, `db`, `ui` (jsdom), `app` (jsdom); pokrycie 100% w roocie.
3. Testy jednostkowe do 100% (core, db, ui, app); test `TechnologyService` na atrapie `em`.
4. `tests/integration/`: globalSetup (testcontainers albo `INTEGRATION_DATABASE_URL`, migracje, `next start`), testy API, serwisu na bazie i przeglądarki (`agent-browser`).
5. `.github/workflows/ci.yml`.
6. AGENTS.md (reguła 100%), README, lessons; lokalna weryfikacja; commit, PR, sprawdzenie przebiegu CI.

## Przebieg

### Krok 0
- `agent-browser` = CLI Vercel Labs (0.39.1). Paczka zawiera natywne binarki; wrapper sam robi `chmod`, więc `postinstall` (blokowany przez npm 11) nie jest potrzebny. Wykrywa zainstalowanego Chrome'a → test przeglądarkowy da się uruchomić lokalnie.
- Akcje GitHub: checkout v7, setup-node v7 (najnowsze majory).

### Krok 1–3 — narzędzia i testy jednostkowe do 100%
- Zainstalowane (root, dev): `@vitest/coverage-v8`, `@testing-library/{react,user-event,jest-dom}`, `jsdom`, `testcontainers`, `@testcontainers/postgresql`, `agent-browser@0.39.1` (przypięty dokładnie). `npm audit` bez nowych alertów.
- Root `vitest.config.ts`: pokrycie v8, `thresholds: { 100: true, perFile: true }`, zakres `packages/*/src/**` + `packages/app/app/**`, wyłączenia: `*.d.ts`, `*.config.{ts,mts}`, migracje. `npm test` = `vitest run --coverage`.
- Projekty `ui` i `app` w `jsdom` z `test/setup.ts` (jest-dom + `cleanup`). `packages/app/vitest.config.mts` — `.mts`, bo pakiet `app` nie ma `"type": "module"` (inaczej ostrzeżenie Vite o ESM w pliku CJS).
- Punkt wyjścia: 41% linii. Wynik: 100% instrukcji/gałęzi/funkcji/linii, 123 testy.
- Zmiany w kodzie produkcyjnym wymuszone przez testy:
  - `getSession` wydzielone do `core/src/http/session.ts` — ścieżka sukcesu `requireSession` była nieosiągalna i nietestowalna (wywołanie w obrębie modułu nie da się podmienić). Wdrożenie auth podmieni tylko ten plik.
  - **Błąd w `CrudForm`:** błędy walidacji klienta na poziomie obiektu (`_form`, np. `refine`) nie były nigdzie wyświetlane. Wspólne `showErrors` dla klienta i serwera. Usunięta martwa gałąź `values[field.name] ?? ""`.
- `TechnologyService` w testach jednostkowych na atrapie `EntityManager` (`core/test/fake-entity-manager.ts`); dotychczasowy test na prawdziwej bazie idzie do `tests/integration/`.
- Problemy: `--project` w Vitest wyłącza zbieranie pokrycia (raport „Unknown”) → pokrycie sprawdzane zawsze pełnym przebiegiem. W `jsdom` `DOMException` nie dziedziczy po `Error` (poprawiona atrapa `fetch`). ESLint lintował raport `coverage/` → dodany do ignorowanych.

### Krok 4–6 — testy integracyjne, CI, dokumentacja
- `tests/integration/`: `vitest.config.ts` (root = katalog, `fileParallelism: false`, timeouty), `global-setup.ts` (baza → migracje przez CLI → `next start` na wolnym porcie → czekanie na zdrowe `/api/health`; `provide`/`inject` dla `baseUrl` i `databaseUrl`), `support/{database,app-server,browser}.ts`.
- Testy: `api.int.test.ts` (health, słownik z migracji, 403/401 bez zmian w danych), `technology-service.int.test.ts` (przeniesiony z core; nie czyści schematu, sprząta tylko rekordy `it-*`; współbieżne wstawienie), `admin-ui.int.test.ts` (agent-browser: `/admin`, `/admin/technologies`, walidacja `CrudForm`, 401).
- Lokalnie (Homebrew, `INTEGRATION_DATABASE_URL` → `devmentor_integration`): 10/10 za pierwszym razem; brak osieroconych procesów `next`/`agent-browser`. Test negatywny (oczekiwane 9 wierszy) → 2 testy przeglądarkowe padają z `expected 8 to be 9` → test faktycznie sprawdza UI.
- `.github/workflows/ci.yml`: `lint`, `unit` (+ artefakt `coverage`), `build` (bez `.env`), `integration` (`agent-browser install --with-deps`, `AGENT_BROWSER_ARGS=--no-sandbox`, `npm run test:integration`). Akcje checkout/setup-node/upload-artifact v7. YAML zweryfikowany.
